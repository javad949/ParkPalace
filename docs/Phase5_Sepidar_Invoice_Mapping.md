## ۱. الزامات و محدودیت‌های قطعی امنیتی (Security Constraints)

سیستم سپیدار به عنوان ERP مالی و انبار رسمی شرکت همکاران، یک سامانه خارجی مستقل است. در اتصال به سپیدار:
1. **دسترسی صرفاً خواندنی (Strict SELECT-Only):**
   - هیچ فرمانی از جنس `INSERT`, `UPDATE`, `DELETE`, `MERGE`, `DROP`, `ALTER` یا اجرای Stored Procedure های تغییردهنده داده روی سرور سپیدار اجرا نمی‌شود.
   - نام کاربری پایگاه داده `crm_reader` با مجوز محدود `db_datareader` تنظیم شده است.
   - تحت هیچ شرایطی از کاربر `sa` یا کاربران مدیر مالی سپیدار استفاده نمی‌شود.
2. **ثبت دستی اسناد رسمی در سپیدار توسط واحد مالی:**
   - واحد مالی اسناد حسابداری، فاکتورهای رسمی و برگه‌های خرید را به صورت دستی در سپیدار ثبت می‌نماید.
   - سامانه CRM از طریق این ماژول، پیشنهادات تطبیق هوشمند را ارائه داده و پس از تأیید حسابدار، شماره و شناسه سند رسمی را به عنوان مرجع (`SepidarVoucherNumber`, `SepidarInvoiceId`) در پایگاه داده CRM ذخیره می‌کند.

```
│  └───────────┬───────────┘   └──────────┬───────────┘  │

│  │ INV.Invoice / PUR.PurchaseInvoice                │  │

```

### ۱.۲. نگاشت فیلدهای فاکتور خرید سپیدار به پایگاه داده CRM

| موجودیت CRM (`SupplierInvoice`) | فیلد متناظر در سپیدار (`INV.Invoice / ACC.Voucher`) | نوع داده | منطق نگاشت و تبدیل |
| :--- | :--- | :--- | :--- |
| `SepidarInvoiceId` | `InvoiceID` / `VoucherID` | `BIGINT` -> `STRING` | شناسه یکتای سیستمی رکورد در دیتابیس سپیدار |

## ۳. الگوریتم پیشنهاد تطبیق هوشمند و ضریب اطمینان (Candidate Matching & Scoring)

از آنجا که خطاهای املایی، تفاوت در تاریخ ثبت سند رسمی با تاریخ صدور فاکتور، یا تفاوت‌های جزئی گردکردن مالیاتی ممکن است رخ دهد، سیستم از یک مدل امتیازدهی چندمعیاره استفاده می‌کند:

```
  ┌─────────────────────────────────────────────────────────────────┐
  │                 Scoring Engine (Confidence 0 to 1.0)            │
  ├───────────────────────────────┬───────────────────┬─────────────┤
  │ معیار ارزیابی                 │ شرط انطباق        │ وزن امتیاز  │
  ├───────────────────────────────┼───────────────────┼─────────────┤
  │ تطبیق شناسه ملی طرف‌حساب       │ برابری دقیق کد ملی │ +۰.۵۰       │
  │ انطباق مبلغ کل با تلورانس ۱٪ │ |Diff| <= 1%      │ +۰.۳۰       │
  │ همزمانی تاریخ (بازه ۱۵ روزه)  │ |DateDiff| <= 15d │ +۰.۲۰       │
  └───────────────────────────────┴───────────────────┴─────────────┘
```

### فرمول محاسبه ضریب اطمینان:
$$\text{Score} = w_{\text{supplier}} + w_{\text{amount}} + w_{\text{date}}$$

### طبقه‌بندی سطوح اطمینان:
- **بالا (High Confidence - $\text{Score} \ge 0.85$):** طرف‌حساب، مبلغ و بازه تاریخی دقیقاً همخوان هستند.
- **متوسط (Medium Confidence - $0.50 \le \text{Score} < 0.85$):** نام یا مبلغ با انحراف جزئی تطبیق دارد و نیاز به دقت کارشناس مالی دارد.
- **پایین (Low Confidence - $\text{Score} < 0.50$):** صرفاً تشابه مبالغ نزدیک؛ احتمال بالای تشابه اسمی نامربوط.

### الزام تأیید قطعی انسانی (Mandatory Human Confirmation):
- **قانون قطعی:** اتصال سند رسمی سپیدار به فاکتور CRM **هرگز به صورت خودکار و بدون تأیید انسان انجام نمی‌شود.**
- کارشناس مالی پس از بررسی کارت سند در رابط کاربری، دکمه «تأیید و اتصال قطعی» را کلیک می‌کند تا مسئولیت ممیزی احراز گردد.

## ۴. چرخه حیات اتصال، لغو اتصال و تاریخچه ممیزی (Link/Unlink & Audit History)

1. **فرآیند اتصال (Link):**
   - کاربر مالی از لیست کاندیداهای پیشنهادی، سند قطعی را انتخاب و متصل می‌کند.
   - وضعیت فاکتور به `RegisteredInSepidar = true` تغییر یافته و فیلدهای مرجع سند سپیدار در فاکتور ذخیره می‌شوند.
   - یک رکورد ممیزی در جدول `SepidarReconciliationAudits` ثبت می‌گردد:
     ```json
     { "Action": "Link", "VoucherNumber": "1403/1029", "ConfidenceScore": 0.95 }
     ```
2. **فرآیند لغو اتصال (Unlink):**
   - در صورت ابطال سند در سپیدار، اصلاح حسابداری یا اشتباه کاربر، امکان Unlink وجود دارد.
   - ثبت **علت لغو اتصال (`Reason`) الزامی است** و کاربر اقدام‌کننده در لاگ تاریخی ممیزی ثبت می‌شود.
   - وضعیت رکورد تطبیق به `Unlinked` تبدیل شده و فاکتور مجدداً آماده پیوند به سند اصلاحی جدید می‌گردد.

## ۵. معماری دوآداپتوره (Dual Adapter Pattern)

به دلیل تفکیک فیزیکی محیط شبکه توسعه از سرور سپیدار در برخی فازها، سیستم بر اساس الگوی Factory/Adapter طراحی شده است:

1. **`SepidarLiveFinancialAdapter` (آداپتور عملیاتی):**
   - برقراری ارتباط با دیتابیس SQL Server سپیدار از طریق رشته اتصال `SepidarConnection` با دسترسی `crm_reader`.
   - اجرای کوئری‌های پارامتریک بهینه و فقط‌خواندنی.
2. **`SepidarFixtureFinancialAdapter` (آداپتور آزمایشی):**
   - شبیه‌ساز منطق کوئری‌ها بر اساس داده‌های استاندارد شده برای اجرای تست‌های یکپارچگی بدون وابستگی به شبکه و دیتابیس بیرونی.
   - تمامی ۲۴ تست یکپارچگی و تست‌های واحد به صورت ۱۰۰٪ موفق با این ساختار اعتبارسنجی شده‌اند.

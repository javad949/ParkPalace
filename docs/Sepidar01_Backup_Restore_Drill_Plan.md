## ۲. مشخصات مقصد آزمایشی، نسخه SQL و اعتبارسنجی میزبان

### ۲.۱. حذف سرور عملیاتی از گزینه‌های بازیابی
* بازیابی روی سرور عملیاتی سپیدار (`SEPIDAR\SEPIDAR` یا IP `192.168.1.242`) در این مرحله **اکیداً ممنوع** است.
* سرور مقصد آزمایشی باید یک نمونه کاملاً مجزا (مانند Staging VM یا نمونه محلی تست) باشد و صریحاً با پارامتر تعیین گردد.

### ۲.۲. الزامات سرور مقصد آزمایشی
1. **نسخه SQL Server:** حداقل SQL Server 2019 (نسخه ۱۵.۰.۲۰۰۰ یا بالاتر) یا SQL Server 2022. موتور SQL امکان بازیابی بکاپ به نسخه پایین‌تر (مانند ۲۰۱۷ یا ۲۰۱۶) را پشتیبانی نمی‌کند.
2. **Collation:** باید با سرور مبدا یعنی `Arabic_CI_AI` سازگار باشد.
3. **اعتبارسنجی هویت میزبان:** اسکریپت در زمان اتصال به مقصد، `@@SERVERNAME` و `@@VERSION` را استعلام کرده و در صورت هرگونه تشابه با سرور عملیاتی، فوراً عملیات را متوقف می‌کند.
4. **بررسی مسیر بکاپ و فضا روی میزبان واقعی:** بررسی وجود فایل، دسترسی و ظرفیت خالی دیسک باید مستقیماً از دیدگاه حساب سرویس سرور مقصد انجام شود؛ بررسی‌های محلی کلاینت (`Test-Path` روی کلاینت) اثبات‌کننده دسترسی سرور SQL به فایل نیست.

## ۳. محاسبات ظرفیت، نگاشت پویا و ایمنی نام‌ها

### ۳.۱. محاسبه قطعی ظرفیت بر مبنای FILELISTONLY
* ظرفیت موردنیاز نباید به‌صورت فرضی یا تخمینی (مانند ۵ تا ۱۰ گیگابایت) لحاظ شود.
* اسکریپت با اجرای `RESTORE FILELISTONLY`، ستون `Size` را برای **تمام فایل‌های درون بکاپ** جمع زده و مقدار دقیق بایت‌ها و مگابایت‌های موردنیاز را پیش از بازیابی استخراج و گزارش می‌کند.

### ۳.۲. نگاشت پویای کلیه فایل‌های درون بکاپ (Dynamic File Mapping)
* ممکن است دیتابیس علاوه بر فایل اصلی داده (`.mdf`) و لاگ (`.ldf`)، دارای فایل‌های ثانویه داده (`.ndf`) یا انواع دیگر باشد.
* اسکریپت برای تک‌تک ردیف‌های بازگردانده‌شده از FILELISTONLY، یک مسیر فیزیکی یکتا تحت پوشه `RelocateDir` ایجاد کرده و عبارت‌های `MOVE N'...' TO N'...'` را به‌صورت پویا تولید می‌نماید.

### ۳.۳. حفاظت از دیتابیس‌ها و فرار رشته‌ها (SQL Escaping)
* **کنترل نام دیتابیس:** نام دیتابیس آزمایشی به فرمت یکتای `Sepidar01_RestoreDrill_20261027_2161` تعریف شده و شامل کاراکترهای مجاز حرفی-عددی است.
* **ممانعت از بازنویسی:** کلیدواژه `WITH REPLACE` به‌طور کامل حذف شده است. اسکریپت با `DB_ID` کنترل می‌کند که هیچ دیتابیسی با نام مقصد وجود نداشته باشد و با `sys.master_files` کنترل می‌کند که مسیرهای فیزیکی فایل‌های مقصد قبلاً استفاده نشده باشند.
* **بررسی فایل‌سیستم میزبان با `sys.dm_os_file_exists`:** علاوه بر کاتالوگ SQL، عدم وجود فایل‌ها روی سیستم‌فایل فیزیکی میزبان بررسی شده و در صورت تلاقی یا عدم امکان بررسی، عملیات متوقف می‌شود.
* **فرار کاراکترها (SQL Escaping):** تمام پارامترها و مسیرهای متنی پیش از الحاق به فرامین SQL، توسط تابع فرار کاراکترها (`Replace("'", "''")`) ایمن‌سازی می‌شوند.

## ۴. تفکیک شواهد در ۳ حالت و مرحله مستقل

```
[حالت ۱: PlanOnly]           --->   [حالت ۲: VerifyBackupOnly]   --->   [حالت ۳: ExecuteRestoreDrill]
(کاملاً آفلاین، بدون شبکه)           (HEADERONLY + VERIFYONLY)            (بازیابی کامل + بررسی واقعی DBCC)
```

### حالت ۱: بررسی طرح به‌صورت کاملاً آفلاین (`PlanOnly`) — *حالت پیش‌فرض*
* کاملاً آفلاین و ایزوله.
* بدون برقراری هرگونه اتصال شبکه یا نشست به SQL Server.
* بدون اجرای دستورات استعلامی (`FILELISTONLY` یا `VERIFYONLY`).
* بدون ایجاد، کپی، تغییر یا حذف فایل‌ها.

### حالت ۲: اعتبارسنجی ساختار بکاپ (`VerifyBackupOnly`)
* اتصال به سرور آزمایشی مجزا.
* اجرای `RESTORE HEADERONLY` و استخراج `Position` دقیق مجموعه بکاپ Sepidar01 به‌صورت کاملاً یکتا (حذف هرگونه Fallback به Position=1 و توقف در صورت ابهام).
* اجرای `RESTORE FILELISTONLY` با موقعیت استخراج‌شده و محاسبه دقیق ظرفیت تمام فایل‌ها.
* بررسی تلاقی مسیر فایل‌ها در کاتالوگ و روی سیستم‌فایل فیزیکی با `sys.dm_os_file_exists`.
* اجرای `RESTORE VERIFYONLY FROM DISK = ... WITH CHECKSUM, FILE = <Position>`.
* *تذکر حقوقی و فنی:* این مرحله صرفاً یکپارچگی فایل بکاپ را تأیید می‌کند و معادل بازیابی آزمایشی موفق نیست. هیچ دیتابیسی در این حالت بازیابی نمی‌شود.

### حالت ۳: بازیابی آزمایشی واقعی، اعتبارسنجی DBCC و حفظ دیتابیس (`ExecuteRestoreDrill`)
* اجرای دستور بازیابی با نگاشت پویای کلیه فایل‌ها:
  ```sql
  RESTORE DATABASE [Sepidar01_RestoreDrill_20261027_2161]
  FROM DISK = N'...'
  WITH FILE = <Position>,
       MOVE N'<LogicalData1>' TO N'D:\SQLData\RestoreDrill\Sepidar01_RestoreDrill_2161_data.mdf',
       MOVE N'<LogicalLog1>' TO N'D:\SQLData\RestoreDrill\Sepidar01_RestoreDrill_2161_log.ldf',
       RESTRICTED_USER,
       NOUNLOAD,
       STATS = 10;
  ```
* **بررسی واقعی و ساختاریافته خروجی DBCC CHECKDB:**
  - دستور `DBCC CHECKDB(...) WITH TABLERESULTS, ALL_ERRORMSGS;` اجرا شده و جدول نتایج مستقیماً اسکن می‌شود.
  - پیام‌های موتور دیتابیس (`InfoMessage`) پایش شده و صرف اتمام متد بدون استثنا به‌عنوان موفقیت تلقی نمی‌شود.
* **حفظ نسخه بازیابی‌شده (عدم حذف خودکار):**
  - کدهای حذف خودکار دیتابیس (`DROP DATABASE`) و `ROLLBACK IMMEDIATE` به‌طور کامل حذف شدند.
  - دیتابیس بازیابی‌شده در حالت **`RESTRICTED_USER`** حفظ می‌شود تا امکان اجرای آزمون‌های فقط‌خواندنی ریدر (Reader Pilot Preview) روی آن فراهم باشد.
  - پاکسازی دیتابیس پس از پایان آزمون‌ها مستلزم تصمیم و مجوز مستقل جداگانه خواهد بود.

## ۵. نتیجه بررسی نمونه‌های محلی SQL Server جهت انتخاب مقصد آزمایشی

بر اساس استعلام فقط‌خواندنی نمونه‌های موجود روی سیستم جاری با هویت ویندوز فعال:

| مشخصه | نمونه اول: `localhost` | نمونه دوم: `localhost\RAD` |
|---|---|---|
| **نام سرور (`@@SERVERNAME`)** | `ORPC` | `ORPC\RAD` |
| **نسخه موتور SQL** | `15.0.2200.2` (SQL Server 2019 CU14) | `13.0.5108.50` (SQL Server 2016 SP2) |
| **ویرایش (Edition)** | Enterprise Edition (64-bit) | Express Edition (64-bit) |
| **Collation پیش‌فرض** | `Arabic_CI_AS` | `Arabic_CI_AS` |
| **مسیرهای پیش‌فرض** | `C:\Program Files\Microsoft SQL Server\MSSQL15.MSSQLSERVER\MSSQL\DATA\` | `C:\Program Files\Microsoft SQL Server\MSSQL13.RAD\MSSQL\DATA\` |
| **دیتابیس‌های موجود** | دیتابیس‌های توسعه CRM، دژاوو، هلو و تانسار | فقط دیتابیس‌های سیستمی (`master`, `model`, `msdb`, `tempdb`) |
| **سازگاری فنی با بکاپ ۲۰۱۹** | **سازگار** (نسخه ۱۵.۰.۲۲۰۰ بزرگتر از ۱۵.۰.۲۰۰۰ مبدا) | **ناسازگار و ناممکن** (خطای ۳۱۶۹ به دلیل نسخه پایین‌تر ۱۳.۰) |

### نتیجه و پیشنهاد مقصد:
1. نمونه `localhost\RAD` به دلیل محدودیت فنی موتور SQL Server 2016 امکان بازیابی بکاپ ۲۰۱۹ را ندارد و به‌طور قطعی کنار گذاشته می‌شود.
2. نمونه `localhost` به دلیل نسخه ۲۰۱۹ CU14 از نظر فنی قابلیت بازیابی را دارد؛ اما از آنجا که دیتابیس‌های توسعه‌ای روی آن مستقر هستند، صرف فعال بودن دلیلی بر اختصاصی بودن آن نیست.
3. **پیشنهاد فنی:** استفاده از `localhost` صرفاً در صورت تأیید صریح، با نام ایزوله `Sepidar01_RestoreDrill_20261027_2161` و مسیر جابه‌جایی اختصاصی در پوشه‌ای مجزا و در وضعیت `RESTRICTED_USER`.

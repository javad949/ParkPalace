## ۱. بازبینی وابستگی‌های زمان اجرا و نیازمندی‌های میزبانی (Runtime Dependencies)

بر اساس بازرسی کدهای منبع، فایل‌های پروژه‌ای (`.csproj`) و تنظیمات پیکربندی، مشخصات فنی لایه‌های سامانه به شرح زیر استخراج و ممیزی شد:

### ۱.۱. وابستگی‌های زمان اجرا (Actual Runtime Dependencies)
* **چارچوب بک‌اند:** **.NET 8.0 (LTS)** با C# 12.
* **پایگاه داده و نگاشت داده:** **Entity Framework Core 8.0.10**، درایور رسمی `Microsoft.Data.SqlClient 5.2.2`.
* **موتور احراز هویت:** `Microsoft.AspNetCore.Authentication.Negotiate 8.0.13` (ارتقایافته جهت بیشترین سطح امنیت).
* **ارتباطات بلادرنگ:** **ASP.NET Core SignalR** جهت مخابره پاپ‌آپ‌های تماس‌های تلفنی.
* **رابط کاربری کلاینت:** **React 18.3.1**, **TypeScript 5.6.2**, **Vite 5.4.21** با معماری کامپوننت‌های بهینه‌شده بدون Tailwind (استفاده از Vanilla CSS و آیکون‌های برداری Lucide).

### ۱.۲. نیازمندی‌های میزبانی در وب‌سرور IIS (IIS Hosting Requirements)
* **نسخه وب‌سرور:** IIS 10 (بر روی Windows Server 2019/2022).
* **پیکربندی وب‌سایت:**
  * **پورت هدف:** `8888` (با پروتکل HTTPS).
  * **Host Header:** `crm.sahar.loc`.
  * **پروتکل WebSocket:** فعال بودن ماژول `WebSocket Protocol` در IIS برای اتصالات بلادرنگ SignalR.
  * **احراز هویت:** فعال بودن `Windows Authentication` (Negotiate/Kerberos) و **غیرفعال بودن قطعی `Anonymous Authentication`**.
  * **ماژول واسط:** نصب **ASP.NET Core Module v2 (ANCM)** در IIS و پکیج Hosting Bundle.

### ۱.۳. نیازمندی‌های سرویس ورکر پس‌زمینه (Worker Requirements)
* اجرای ماژول `ParkPalace.Worker` یا Background Service داخلی جهت:
  * زمان‌بندی همگام‌سازی دوره‌ای موجودی و اسناد انبار از سپیدار (هر ۶۰ دقیقه).
  * شنود پایدار رویدادهای تماس تلفنی از طریق سوکت AMI ایزابل (پورت ۵۰۳۸).
  * مدیریت بازیابی خودکار و اتصال مجدد (Auto-reconnect with Exponential Backoff).

### ۱.۴. نیازمندی‌های پایگاه داده و تراکنش‌ها (Database Requirements)
* **پایگاه داده CRM:** یک پایگاه داده مجزا با نام `ParkPalaceCRM_DB` روی SQL Server.
* **پایگاه داده مالی سپیدار:** دسترسی به پایگاه داده `Sepidar01` (روی IP `192.168.1.242,62753`) با سیاست اکید **SELECT-Only** (حساب اختصاصی بدون دسترسی INSERT/UPDATE/DELETE).
* **زنجیره مایگریشن‌ها:** ۵ مرحله مایگریشن EF Core رسمی با متدهای معکوس متقارن `Down()` جهت تضمین بازگشت‌پذیری (Reversibility).

### ۱.۵. احراز هویت و سطوح دسترسی نقشی (Authentication & RBAC)
* اتصال بدون پسورد از طریق تیکت‌های Kerberos به دامین `sahar.loc`.
* تنظیم Service Principal Name (SPN) به صورت `HTTP/crm.sahar.loc` بر روی حساب سرویس اختصاصی وب‌سایت.
* پیاده‌سازی ۷ نقش و دسترسی تفکیک‌شده:
  1. `Permissions.MaterialsManage`
  2. `Permissions.SuppliersManage`
  3. `Permissions.OrdersManage`
  4. `Permissions.InventoryView`
  5. `Permissions.FinanceMatch`
  6. `Permissions.CallsView`
  7. `Permissions.ReportsView`

### ۱.۶. مدیریت اسرار و گواهینامه‌ها (Secrets & Certificates)
* الزام گواهینامه معتبر SSL/TLS سازمانی برای دامین `crm.sahar.loc`.
* عدم ذخیره پسوردهای اتصالات سپیدار یا AMI در فایل‌های متنی `appsettings.json` در محیط عملیاتی؛ الزام استفاده از Windows Credential Manager یا DPAPI.

* **اسکریپت پشتیبان‌گیری کامل با Checksum:** در سند [Phase8_Rollback_And_Recovery.md](file:///D:/ParkPlace/docs/Phase8_Rollback_And_Recovery.md) تدوین گردید. اعتبارسنجی با `RESTORE VERIFYONLY WITH CHECKSUM` به عنوان پیش‌نیاز تعریف شده است.

* **وضعیت در محیط فیزیکی عملیاتی:** **NOT VERIFIED (تست بازیابی فیزیکی روی سخت‌افزار واقعی سرور انجام نگرفته و نیازمند پنجره نگهداری عملیاتی با مجوز مدیر شبکه است).**
* **اهداف بازیابی تعریف‌شده:**
  * **RTO (Recovery Time Objective):** کمتر از ۱۵ دقیقه جهت بازگردانی دیتابیس و کمتر از ۲ دقیقه جهت سوییچ فایل‌های وب در IIS.
